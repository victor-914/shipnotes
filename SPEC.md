# Outcome Snapshot — `outcomes/0.1`

An Outcome Snapshot is one JSON document that says how a project did over one period: a few numbers, what they were before, and what shipped. Any project in any language can publish one. Tools like shipnotes read it; they never need access to your database.

Machine-readable schema: [`schema/outcomes.schema.json`](schema/outcomes.schema.json).

## Where to publish it

Any of these work:

- an endpoint, conventionally `GET /.well-known/outcomes.json`, behind a read-only key if the numbers are not public;
- a file committed to the repo, regenerated by CI;
- a file written by a cron job.

It should return **totals only**: no names, emails, IDs or anything about individual people.

## Example

```json
{
  "spec": "outcomes/0.1",
  "project": { "name": "Casmir Realty", "slug": "casmir-realty", "url": "https://casmirshortlets.com" },
  "period": { "from": "2026-11-03", "to": "2026-11-10" },
  "north_star": "paid_bookings",
  "metrics": [
    { "name": "lighthouse_performance", "value": 73, "previous": 53, "unit": "score", "public": true },
    { "name": "lcp_seconds", "value": 2.7, "previous": 6.3, "unit": "seconds", "better": "lower", "public": true },
    { "name": "paid_bookings", "value": 12, "previous": 7, "unit": "count", "public": false }
  ],
  "shipped": [{ "title": "Speed up the homepage", "date": "2026-11-09", "ref": "commit:9f1c2ab" }]
}
```

## Fields

| Field | Required | Meaning |
|---|---|---|
| `spec` | yes | Always `"outcomes/0.1"` for this version. |
| `project.name` | yes | Display name. |
| `project.slug` | yes | Lowercase, hyphenated, stable. Used to link posts to projects. |
| `project.url`, `project.description` | no | Linked and quoted in posts. |
| `period.from`, `period.to` | yes | Dates (`YYYY-MM-DD`), inclusive. `previous` values describe the period of the same length just before. |
| `north_star` | no | The `name` of the one metric that matters most. Must be in `metrics`. |
| `metrics[]` | yes | Up to 100. May be empty. |
| `shipped[]` | no | What changed in the period. Tools may add more (for example from git). |
| `generated_at` | no | ISO date-time the snapshot was produced. |

### Metric

| Field | Required | Meaning |
|---|---|---|
| `name` | yes | `lowercase_with_underscores`, unique in the snapshot. |
| `label` | no | Human wording, e.g. "Paid bookings". |
| `value` | yes | The number for this period. |
| `previous` | no | The number for the period before. Without it, tools cannot report a change. |
| `unit` | no | `count` (default), `ratio` (0–1), `percent` (0–100), `seconds`, `ms`, `score`, `currency`. |
| `currency` | with `currency` | ISO 4217 code, e.g. `NGN`. |
| `better` | no | `higher` (default) or `lower`. Load time is better lower. |
| `public` | no | **Defaults to `false`.** Only public metrics may appear in anything published. |

### Shipped item

| Field | Required | Meaning |
|---|---|---|
| `title` | yes | One line, as you'd say it to a customer if you can. |
| `date` | yes | `YYYY-MM-DD`. |
| `ref`, `url` | no | Commit, PR or release reference. |

## Rules for tools that read snapshots

1. **Private by default.** A metric without `"public": true` must not be published, and should not be sent to a language model.
2. **No invented numbers.** Anything published must only contain numbers taken from snapshots, or simple roundings of them.
3. **No implied causes.** Report what shipped and what moved in the same period; don't claim one caused the other.
4. **Drafts, not posts.** A person approves before anything goes public.

## Versioning

`outcomes/0.x` may change between minor versions. Tools should reject a `spec` value they don't know rather than guess.
